# TASK-0074: Fallback Valuation & Zero FV Protection

## MỤC TIÊU
Loại bỏ triệt để lỗi chia cho 0 (`ZeroDivisionError`) khi tính toán Biên an toàn (Margin of Safety), và áp dụng chiến thuật KBS-First cho dữ liệu Báo cáo Tài chính nhằm đảm bảo độ tươi mới và tránh các lỗi đóng băng dữ liệu từ nguồn VCI (VD: nhóm Ngân hàng/Chứng khoán).

## CHI TIẾT VẤN ĐỀ
- Tại Phase 20, một số mã chứng khoán (như `SSI`) từ API VCI trả về BCTC bị khuyết hoặc hỏng (Fair Value tính ra bằng 0.0).
- Hàm tính `mos_pct = ((price_base - current_price) / price_base) * 100` trong `quant_engine.py` nhận `price_base = 0` dẫn đến lỗi toán học `ZeroDivisionError`, làm văng ứng dụng tương tự TASK-0073.
- Bên cạnh đó, VCI thường xuyên bị lỗi "Đóng băng" số liệu P/B cũ từ năm 2018 đối với nhiều mã lớn (FPT, MWG, TCB, VHM).

## GIẢI PHÁP
1. **Phòng vệ toán học (Zero FV Protection):** Tại `quant_engine.py`, thêm hàm logic an toàn:
   ```python
   fallback_mos = round(((price_base - current_price) / price_base) * 100, 2) if price_base > 0 else 0.0
   ```
2. **Kiến trúc KBS-First, VCI-Fallback:** Đảo ngược logic lấy BCTC tại `data_engine.py`. Nguồn KBS (ổn định hơn) sẽ được dùng để bóc tách các chỉ số cốt lõi (P/E, P/B, ROE) làm định giá. Nguồn VCI chỉ đóng vai trò thứ cấp (fallback) nhằm lấy các chỉ số chuyên sâu (ROIC, EV/EBITDA, v.v.).
